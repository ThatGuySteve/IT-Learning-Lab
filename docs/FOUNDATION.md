## Executed upstream checks

- NetSim: `npm ci --ignore-scripts`, `npm test`: **72/72 passed**, 7 files; `npm run build`: **passed**. Its existing VLAN test establishes a same-VLAN success and a different-VLAN failure, but does not itself prove our repair/revert workflow; our own tests cover that.
- NetQuest: `python3 -m pip install -r backend/requirements-dev.txt`; `cd backend && python3 -m pytest -q`: **283/283 passed**, one Starlette deprecation warning. `cd frontend && npm ci --ignore-scripts && npm run build`: **passed**. These passing tests do not imply VLAN support.
- REA: inspected source and metadata only; its build and test suite were **not run**.

## Licensing and dependency observations

NetSim's full app declares React, xterm, XYFlow, fflate, lz-string and Zustand plus development tooling. A metadata scan of 124 installed top-level npm packages in that checkout found MIT (104), ISC (14), Apache-2.0 (3), BSD-3-Clause (2), and CC-BY-4.0 (1); this is a metadata inventory, not a legal audit. The copied engine subset has **no external imports** and includes the complete upstream MIT license at `licenses/NETSIM-MIT.txt`. Its ten copied files were byte-compared with that revision.

NetQuest declares FastAPI, Uvicorn and Pydantic on the backend plus React, XYFlow, Lucide and Zustand on the frontend. A metadata scan of 61 installed top-level frontend packages reported MIT (44), ISC (11), BSD-3-Clause (2), Apache-2.0 (2), and MPL-2.0 (2). Selected installed Python package metadata reported MIT or BSD-3-Clause; this was not a complete legal review of its transitive graph. None of NetQuest is distributed in this project.

This app's locked production npm packages are React, React DOM, Scheduler and Zod, each MIT, with their original license texts retained. Development dependencies and any eventual Rust/Tauri bundle have their own transitive terms. **The Windows Rust dependency graph and packaged notices have not yet been audited; do not treat an experimental installer as a reviewed release.**

## Tradeoffs and boundary

The adapter builds an in-memory network from the current port assignments for each probe, sends an actual NetSim ICMP echo, advances its virtual clock, and waits for the destination reply. Starting fresh deliberately removes stale ARP and MAC caches between probes; persistence stores the configuration and learner actions, not live packet state. This makes repeat verification deterministic, but does not teach cache aging or production timing.

Only one switch with untagged access ports, static IPv4 and selected ARP/ICMP exchanges is exposed. No trunking, VLAN routing, DHCP, DNS, live printer spooler, authentic vendor CLI, real device network access or packet-accurate emulation is claimed. NetSim [documents](https://github.com/michael-borck/netsim/blob/c3075e7fe65b7e17515d802eaef625bab751af58/docs/USER_GUIDE.md) further limits including no 802.1Q trunking. Upstream activity and features can change; reevaluate before extending or upgrading.
